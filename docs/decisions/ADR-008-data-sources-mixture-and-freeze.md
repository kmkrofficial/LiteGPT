# ADR-008: Data sources, mixture, partitions, tokenizer and validation freeze

Status: Accepted
Date: 2026-10-11
Spec fields: `tokenizer.*`, `data.*` (spec 2.0.0-spec.6); `docs/spec/data_sources.yaml`

## Context

M1 prepares everything training needs: sources, tokenizer, 15.5B tokens, a frozen validation set and a resumable loader. Between
the approved plan and now, source verification and audits (2026-10-07) and a pre-flight (2026-10-11) produced facts that change
details of the plan: two candidate code datasets ship only blob ids, Wikipedia was excluded by the owner for licence reasons, the
owner asked for a Python/JS/TS/SQL/Shell-focused code mix, and the decay instruction data was generated by Llama and Qwen models.

## Decision

1. **Sources** are pinned to exact Hub revisions in `docs/spec/data_sources.yaml` (FineWeb-Edu dedup, Cosmopedia v2, FineMath 3plus,
   `codeparrot/github-code-clean`, three Apache-2.0-labelled SmolTalk subsets). Wikipedia is excluded.
2. **Mixture** (Wikipedia redistributed proportionally, instruction slice fixed at 5% of decay):
   stable FineWeb-Edu 64.58 / Cosmopedia 10.42 / code 12.50 / math 12.50; decay 43.18 / 12.95 / 17.27 / 21.59 / instruction 5.00.
3. **Code** is Python 63 / JavaScript 14 / TypeScript 14 / SQL 4 / Shell 5 (percent of code tokens), permissive licences only,
   files 0-222 of `github-code-clean`, with the filters in `litegpt/datafilters.py`. The weights follow the pre-registered C4 rule
   (SQL fell short at 5%). This is a **design judgement**, not a measured result: the proxy ladder cannot resolve it.
4. **Partitions** are hash-based and deterministic; a code repository is never split. Decay uses the top quality tier where a source
   has one (`int_score >= 4`). Validation is disjoint by construction.
5. **Decontamination filters pretraining data** (13-gram word overlap with 18 pinned evaluation sets); the spec's earlier
   "spot-check" is superseded.
6. **Document keys and BOS/EOS**: each document is stored as `<|bos|> tokens <|endoftext|>`; special ids are inserted explicitly
   and never parsed from text.
7. **The chat renderer** (`litegpt-chat-v1`, `render(messages) -> ids`) moves forward to M1 because the instruction slice and the
   chat validation domain need it. Loss masks and the Jinja template stay in M4.
8. **Deduplication**: none beyond what the sources provide; exact cross-source duplicates are measured and reported, and a rate above
   1% of any source's tokens returns the decision to the owner.
9. **Freeze**: the tokenizer (`sha256`), `val_core` (`sha256`) and the data order (`data_order_sha256`) are recorded in the spec at
   M1 Checkpoint B / step 6. Changing any of them afterwards needs a new ADR.

## Alternatives rejected

- **`HuggingFaceTB/stack-edu` / `smollm-corpus` python-edu:** only blob ids, no text.
- **`bigcode/starcoderdata`, `the-stack-dedup`:** gated; the audit showed `github-code-clean` has ample Python and other code.
- **Broad code mix (14 languages):** spreads about 1.9B code tokens too thin for a 200M model; focus gives depth.
- **File-level code partitioning:** would leak a repository into validation.
- **Cross-source deduplication pass:** order-dependent and two-pass; cost exceeds the expected gain at these source sizes.
- **Wikipedia kept with a share-alike note:** the owner chose to avoid CC BY-SA / GFDL ambiguity in the release model.

## Consequences

- The licence register carries three items to the M5 gate: Llama 3.1 naming (Smol-Magpie-Ultra, M4 only), the Qwen2.5-72B display
  requirement (decay instruction slice), and repository-level code licence labels. The owner decided on 2026-10-11 that the Qwen
  clause is not a blocker for M1; it stays recorded.
- Prepared download is about 125 GB and 15.5B tokens (about 31 GB of shards) on the WSL disk.
- Token counts in `data_sources.yaml` use the GPT-2 tokenizer as a proxy; Checkpoint B re-derives file lists with the real tokenizer.
