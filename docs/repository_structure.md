# Repository structure

Decision record: [ADR-007](decisions/ADR-007-repository-structure.md).

```
litegpt/        canonical production source (the only importable package); api.py and cli.py are the user-facing entry points
tests/          canonical tests
benchmarks/     reusable benchmark scripts and tooling (results go to runs/)
scripts/        reusable utilities; scripts/legacy_v1/ is the preserved V1 baseline
scratch/        temporary experiments and prototypes (git-ignored)
runs/           all generated experiment outputs
docs/           permanent docs, ADRs, spec/ (specification)
```

Each top-level folder has a README saying what is in it. Root files: `README.md`, `CHANGELOG.md`, `LICENSE`, `pyproject.toml`, `uv.lock`, `.gitignore`, `.gitattributes`.

## Rules

1. **Production code lives in `litegpt/` only**, with tests in `tests/`. No experimental or duplicate implementations there.
   Nothing in `litegpt/`, `benchmarks/` or `scripts/` imports from `scratch/`.
2. **Temporary experiments go in `scratch/`.** Promote what proves useful (tooling to `scripts/` or `benchmarks/`, tested code to
   `litegpt/`), then delete it from `scratch/`.
3. **Benchmark scripts stay in `benchmarks/`; their results go to `runs/<run-id>/`**, created with `litegpt.records.create_run`
   (which writes `run.json` with the spec hash, git state and full environment fingerprint).
4. **Everything generated lives in `runs/`**: logs, metrics, telemetry, figures, reports, manifests, other artifacts. There is no
   top-level `reports/` directory; the generated report is `runs/report-latest/`.
5. **Historical runs are never deleted.** They are the provenance for every number in a report.

## `runs/` layout and git policy

```
runs/<run-id>/            run.json  metrics.jsonl  telemetry.jsonl  bench/*.json  eval/*.json  gate/*.json  (figures, ...)
runs/report-latest/       REPORT.md + figures/*.svg, generated by `python -m scripts.build_report` (never edited by hand)
```

`<run-id>` = `<UTC timestamp>-<kind>-<name>-<git short sha>`; kinds: `train eval bench data export test`.
Committed: `run.json`, result files, `metrics.jsonl`, figures and the generated report. Ignored: `telemetry.jsonl`, `checkpoints/`,
`shards/`, `raw/`, and `*.pt` / `*.bin` / `*.safetensors` anywhere. `python -m scripts.build_report --check` fails if the
committed report no longer matches the run records.

## Where future components go

| Component | Location |
|---|---|
| inference engine, chat template, tokenizer wrapper, training loops, eval harness and adapters, HF export, quantization | `litegpt/` subpackages (`litegpt/inference/`, `litegpt/training/`, `litegpt/eval/`, `litegpt/export/`) |
| data-preparation entry points, tokenizer training, decontamination runs | `scripts/` (their outputs: shards and manifests under `runs/`) |
| new benchmark scripts | `benchmarks/` |

## V1 baseline (`scripts/legacy_v1/`)

The V1 code, configs, data-preparation scripts, notebooks and HF inference helpers, moved with `git mv` (history preserved). It is
kept only to reproduce V1 baselines and is not imported by `litegpt/` (the report builder reads its `model.py` for the V1 column).
Run V1 scripts from inside that directory, e.g. `cd scripts/legacy_v1 && python train.py config/train_fineweb.py`; its relative paths
(`configurator.py`, `data/<dataset>/`, `out-*/`) are unchanged.
