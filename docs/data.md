# Data

**Status: final; used for M3 and M4.** Binding configuration: [`docs/spec/data_sources.yaml`](spec/data_sources.yaml) and spec `data.*` / `tokenizer.*`
(2.0.0-spec.6, [ADR-008](decisions/ADR-008-data-sources-mixture-and-freeze.md)). Measured numbers (tokens per source,
filter and decontamination rates, duplicates, frozen hashes) are in section 3c of the generated report
(`runs/report-latest/REPORT.md`); licences and provenance are in [data_licenses.md](data_licenses.md).

## Mixture

Stable phase (to 9B tokens, or 14B if the G1 gate extends): FineWeb-Edu 64.58%, Cosmopedia 10.42%, code 12.50%, math 12.50%.
Decay (the last 1B tokens, identical in both gate outcomes): 43.18 / 12.95 / 17.27 / 21.59%, instruction-style 5.00%.

## Pipeline

```
download one parquet file (exact revision) -> read documents -> code filters (litegpt/datafilters.py)
  -> 13-gram decontamination (litegpt/decontam.py, 18 pinned benchmarks) -> hash partition (val / decay / stable)
  -> tokenize (frozen 32k tokenizer; <|bos|> ... <|endoftext|> per document) -> uint16 shards + per-file stats
  -> delete the downloaded file
```

- **Partitions** are a deterministic function of `sha256(salt:source:key)`, so preparation is parallel and resumable, and a
  validation document can never be in a training partition. Code is partitioned by repository.
- **Code filters**, in order: file size, line length, alphanumeric fraction, auto-generated header, vendored / minified paths,
  library mirrors, Python 3 parse, SQL data dumps, SQL export dumps, copyleft header, secrets (dropped); e-mail addresses are
  redacted to `<EMAIL>`.
- **Decontamination** drops any document sharing a word 13-gram with an evaluation item. Reference 13-grams made only of
  numbers or single characters are excluded: they are generic sequences, not benchmark text (audit in EXP-M1-DECONTAM).
- **Special tokens** are only ever inserted explicitly; literal special-token text inside a document is ordinary text.

## Training order and loading

Tokens are stored once. The order is a small index of `(source, block)` pairs: a smooth weighted round-robin over sources
(exact proportions at every prefix) with a seeded permutation of each source's 2,048-token blocks. Indexes: `stable`
(14B tokens), `decay` (1B), `val_core` (10,240 blocks), one per validation domain, `proxy_1b` and `proxy_1b_nocodemath`
(M2 steps 7–8), `proxy_gpt2_train` / `proxy_gpt2_val` (M2 steps 1–6, GPT-2 tokens). `litegpt.data.MixtureLoader` reads them;
its whole state is one integer, stored in the checkpoint's `data_position`, which gives exact resume.

## Validation

- `val_core`: 10,240 blocks (20.97M tokens) in the stable mixture's proportions; frozen with the sha256 of its token
  content in the spec. It is the evaluation set of the G1 extension gate.
- Domain sets (web, synthetic, code, math, chat): 1,024 blocks each.
- `val_text/<domain>.jsonl`: about 2 MB of whole raw-text validation documents per domain, for bits-per-byte of models with
  other tokenizers (M1b baselines). Not committed to git (raw dataset text); its sha256 is in the report.

## Reproduce

```bash
python scripts/decontaminate.py build                       # 13-gram index from the pinned benchmarks
python scripts/prepare_data.py prepare --tokenizer litegpt/assets/tokenizer/litegpt-32k.json --ngrams <index run>/ngrams.npz
python scripts/prepare_data.py mix --run <data run>          # indexes, checks, val_text, frozen hashes
```

Run in WSL2 on the ext4 disk (about 143 GB downloaded and deleted file by file, about 31 GB of shards). The same inputs give
bit-identical shards and indexes.
